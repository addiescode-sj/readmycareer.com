# User Stories — Personal Career Manager AI Agent

> 📄 PRD 기반 생성 | 총 20개 스토리 | 생성일: 2026-04-13
> 확정 사항: RAG 풀스택 포함 / 계정 기반 / 대화 히스토리 DB 저장

## Epic 1: 사용자 프로필 입력 및 계정 관리
> 취업 준비자가 자신의 이력과 목표를 시스템에 등록하고, 세션 간 데이터를 유지할 수 있는 기반을 제공한다.

### US-001 | 🔴 Must | 이메일로 회원가입

- **Page:** 회원가입 화면
- **Feature:** 이메일 인증 기반 계정 생성

**As a** 커리어 전환을 준비 중인 개발자,
**I want to** 이메일과 비밀번호로 계정을 만들고,
**So that** 이력서와 로드맵 데이터를 저장해 다음 접속 시 이어서 사용할 수 있다.

**Acceptance Criteria:**
- [ ] Given 회원가입 폼에 유효한 이메일·비밀번호를 입력했을 때, When 가입 버튼을 누르면, Then 이메일 인증 메일이 발송된다.
- [ ] Given 인증 링크를 클릭했을 때, When 링크가 유효하면, Then 계정이 활성화되고 대시보드로 이동한다.
- [ ] Given 이미 가입된 이메일을 입력했을 때, When 가입 버튼을 누르면, Then "이미 사용 중인 이메일입니다" 오류 메시지가 표시된다.
- [ ] Given 비밀번호가 8자 미만인 경우, When 가입 버튼을 누르면, Then 인라인 유효성 오류가 즉시 표시된다.

---

### US-002 | 🔴 Must | 이력서 PDF 업로드

- **Page:** 프로필 입력 화면
- **Feature:** PDF 파싱 및 텍스트 추출

**As a** 취업 준비 중인 개발자,
**I want to** 내 이력서 PDF를 업로드하면 기술 스택과 프로젝트 경험이 자동으로 파싱되기를,
**So that** 수동 입력 없이 빠르게 갭 분석을 시작할 수 있다.

**Acceptance Criteria:**
- [ ] Given PDF 파일을 업로드했을 때, When 파싱이 완료되면, Then 기술 스택·프로젝트·경력 기간이 구조화된 프리뷰로 표시된다.
- [ ] Given 파싱 결과를 확인했을 때, When 사용자가 항목을 수정·추가하면, Then 변경 사항이 저장된다.
- [ ] Given PDF 용량이 10MB를 초과할 때, When 업로드를 시도하면, Then 파일 크기 초과 안내 메시지가 표시된다.
- [ ] Given 스캔 이미지 PDF처럼 텍스트 추출이 불가능한 경우, Then 수동 입력 모드로 안내한다.

**Notes:** 서버 사이드 PDF 파싱(pdf-parse 또는 Python pdfminer). 추출 결과는 JSON 스키마로 정규화해 DB 저장.

---

### US-003 | 🔴 Must | 수동 기술 스택 입력

- **Page:** 프로필 입력 화면
- **Feature:** 태그 기반 기술 스택 직접 입력

**As a** PDF 업로드를 원하지 않는 개발자,
**I want to** 기술 스택과 프로젝트 경험을 직접 텍스트로 입력하고,
**So that** 이력서 없이도 갭 분석을 시작할 수 있다.

**Acceptance Criteria:**
- [ ] Given 기술 스택 입력 필드에서 태그를 입력할 때, When 엔터 또는 쉼표를 누르면, Then 태그가 추가되고 자동완성 후보가 표시된다.
- [ ] Given 프로젝트 경험 입력 시, Then 프로젝트명·사용 기술·기간을 최소 단위로 입력할 수 있는 구조화된 폼이 제공된다.
- [ ] Given 필수 필드(경력 연수, 기술 스택 1개 이상)가 비어 있을 때, When 다음 단계로 이동하면, Then 필수 항목 오류가 표시된다.

## Epic 2: 목표 설정 및 JD 탐색
> 사용자가 목표 회사·직군·취업 기간을 설정하고 관련 JD를 RAG로 조회할 수 있는 흐름을 제공한다.

### US-004 | 🔴 Must | 취업 목표 설정

- **Page:** 목표 설정 화면
- **Feature:** 목표 회사·직군·기간 입력

**As a** 커리어 전환을 계획 중인 개발자,
**I want to** 목표 회사명, 직군(예: Product Engineer), 취업 목표 기간을 입력하고,
**So that** AI가 해당 맥락에 맞는 JD 기반 갭 분석을 수행할 수 있다.

**Acceptance Criteria:**
- [ ] Given 회사명 입력 시, Then 자동완성으로 알려진 회사 목록이 제안된다.
- [ ] Given 취업 기간을 설정할 때, Then 1주~6개월 범위에서 선택 가능하고, 시스템은 오늘 날짜 기준으로 마감일을 자동 계산한다.
- [ ] Given 목표 설정을 저장했을 때, Then 이후 모든 분석과 로드맵이 해당 목표를 기준으로 생성된다.
- [ ] Given 동일 계정에서 목표를 재설정하면, Then 기존 로드맵을 덮어쓸지 새로 생성할지 선택 다이얼로그가 표시된다.

---

### US-005 | 🔴 Must | RAG 기반 JD 자동 조회

- **Page:** 목표 설정 화면 → 분석 결과 화면
- **Feature:** Vector DB 유사 JD 검색

**As a** 목표 직군을 설정한 개발자,
**I want to** 목표 회사·직군을 입력하면 관련 JD가 자동으로 검색되기를,
**So that** 내가 직접 JD를 찾아 붙여넣는 번거로움 없이 분석이 시작된다.

**Acceptance Criteria:**
- [ ] Given 목표가 설정됐을 때, Then 기술 스택 조합 쿼리로 Vector DB에서 관련도 상위 3~5개 JD가 자동 검색된다.
- [ ] Given JD 검색 결과가 표시될 때, Then 각 JD의 출처(회사명, 직군, 수집일)와 관련도 점수가 함께 표시된다.
- [ ] Given 사용자가 검색된 JD 중 일부를 제외하면, Then 선택된 JD만으로 갭 분석이 수행된다.
- [ ] Given 관련 JD가 없을 때, Then "JD를 직접 붙여넣기" 옵션이 안내된다.

**Notes:** tech stack combinations을 임베딩 쿼리로 사용. Supabase Vector 또는 Pinecone pgvector 연동.

---

### US-006 | 🟡 Should | JD 직접 붙여넣기

- **Page:** 목표 설정 화면
- **Feature:** 커스텀 JD 텍스트 입력

**As a** 특정 공고를 직접 가져온 개발자,
**I want to** JD 전문을 텍스트로 붙여넣어 분석에 사용하고,
**So that** Vector DB에 없는 신규 공고에도 분석을 적용할 수 있다.

**Acceptance Criteria:**
- [ ] Given JD 텍스트를 입력창에 붙여넣었을 때, When "분석에 추가" 버튼을 누르면, Then 해당 JD가 분석 대상 목록에 추가된다.
- [ ] Given 입력 텍스트가 500자 미만일 때, Then "JD 내용이 너무 짧습니다" 안내가 표시된다.
- [ ] Given 직접 입력한 JD는, Then 자동 검색된 JD와 동일한 형식으로 분석에 사용된다.

## Epic 3: 프로필-JD 갭 분석
> AI가 사용자 프로필과 JD를 심층 비교해 부족 역량과 우선순위를 근거와 함께 제시한다.

### US-007 | 🔴 Must | 역량 갭 분석 결과 조회

- **Page:** 갭 분석 결과 화면
- **Feature:** 현재 역량·부족 역량·개선 우선순위 표시

**As a** 갭 분석을 요청한 개발자,
**I want to** 내 현재 역량, 부족한 역량, 개선 우선순위를 한 화면에서 확인하고,
**So that** 무엇을 먼저 공부해야 하는지 즉시 파악할 수 있다.

**Acceptance Criteria:**
- [ ] Given 분석이 완료됐을 때, Then 현재 역량·부족 역량·개선 우선순위 3개 섹션이 명확히 구분돼 표시된다.
- [ ] Given 부족 역량 항목마다, Then 어느 JD의 어떤 요구사항과 매칭됐는지 근거(출처 JD + 요구사항 텍스트)가 함께 표시된다.
- [ ] Given 분석 결과를, Then 단순 키워드 매칭이 아닌 프로젝트 경험의 깊이와 JD 요구 수준의 논리적 비교로 생성한다.
- [ ] Given 분석 중 로딩 상태일 때, Then 진행 단계(JD 조회 → 비교 분석 → 결과 생성)가 단계별 인디케이터로 표시된다.

**Notes:** Few-shot 프롬프트에 [Junior Frontend / Target: Toss] 형태의 예시 포함. 출력은 JSON 스키마로 강제.

---

### US-008 | 🟡 Should | 갭 분석 결과 재생성

- **Page:** 갭 분석 결과 화면
- **Feature:** 분석 재실행

**As a** 분석 결과가 기대와 다른 개발자,
**I want to** JD를 교체하거나 프로필을 수정한 후 분석을 다시 실행하고,
**So that** 더 정확한 갭 결과를 얻을 수 있다.

**Acceptance Criteria:**
- [ ] Given 프로필 또는 JD를 수정했을 때, Then "재분석" 버튼이 활성화된다.
- [ ] Given 재분석 버튼을 눌렀을 때, Then 기존 결과와 새 결과가 나란히 비교되거나 새 결과로 교체된다.
- [ ] Given 재분석 결과가 이전과 다를 때, Then 변경된 항목이 하이라이트된다.

---

## Epic 4: 로드맵 생성 및 시각화
> 갭 분석 결과를 기반으로 타임라인·주간 To-do·일일 학습 로그를 자동 생성하고 시각적으로 제공한다.

### US-009 | 🔴 Must | 타임라인 로드맵 생성

- **Page:** 로드맵 화면
- **Feature:** 단계별 타임라인 테이블 생성

**As a** 갭 분석을 완료한 개발자,
**I want to** 취업 기간 전체를 준비→집중 학습→지원·면접 단계로 나눈 타임라인 로드맵을 받고,
**So that** 어느 시기에 무엇을 해야 하는지 한눈에 파악할 수 있다.

**Acceptance Criteria:**
- [ ] Given 취업 목표 기간이 설정됐을 때, Then 오늘 날짜 기준으로 단계가 자동 계산된 타임라인 테이블이 생성된다.
- [ ] Given 타임라인이 표시될 때, Then 각 단계(준비·집중학습·지원·면접)의 시작일·종료일·핵심 목표가 표시된다.
- [ ] Given 타임라인 데이터가 생성될 때, Then Mermaid.js 또는 커스텀 UI 컴포넌트로 렌더링 가능한 구조화 데이터(JSON/Markdown)로 출력된다.
- [ ] Given 현재 날짜가 특정 단계 내에 있을 때, Then 해당 단계가 시각적으로 강조된다.

---

### US-010 | 🔴 Must | 주간 To-do 리스트 생성

- **Page:** 로드맵 화면 — 주간 뷰
- **Feature:** JD 기반 주차별 액션 아이템 생성

**As a** 로드맵을 받은 개발자,
**I want to** 각 주차별로 구체적인 학습 액션 아이템을 확인하고,
**So that** 매주 무엇을 해야 하는지 명확히 알고 실행할 수 있다.

**Acceptance Criteria:**
- [ ] Given 로드맵이 생성됐을 때, Then 각 주차에 부족 역량 기반의 구체적 액션 아이템(예: "Next.js App Router로 RAG 파이프라인 프로젝트 구축")이 최소 3개 제안된다.
- [ ] Given 주간 아이템이 표시될 때, Then 각 항목은 완료 체크박스와 함께 표시되고, 완료 처리 시 DB에 저장된다.
- [ ] Given 특정 주차를 클릭하면, Then 해당 주의 상세 계획이 펼쳐진다.

---

### US-011 | 🔴 Must | 일일 학습 로그 템플릿 생성

- **Page:** 로드맵 화면 — 일일 뷰
- **Feature:** 일일 학습 기록 템플릿 및 체크리스트

**As a** 매일 학습을 기록하고 싶은 개발자,
**I want to** 오늘의 학습 내용을 요약하는 템플릿과 다음 단계로 넘어가기 위한 체크리스트를 받고,
**So that** 학습 진척도를 체계적으로 추적할 수 있다.

**Acceptance Criteria:**
- [ ] Given 일일 뷰를 열었을 때, Then 오늘 날짜의 학습 요약 텍스트 입력 영역과 완료 체크리스트가 표시된다.
- [ ] Given 체크리스트 항목을 모두 완료했을 때, Then "다음 단계로 진행 가능" 상태가 시각적으로 표시된다.
- [ ] Given 하루가 지나면, Then 해당 날의 로그가 자동으로 아카이브되고 히스토리에서 조회 가능하다.
- [ ] Given 로그를 저장하면, Then DB에 날짜·내용·완료 체크리스트 상태가 함께 저장된다.

---

### US-012 | 🟡 Should | 타임라인 토글 시각화

- **Page:** 로드맵 화면
- **Feature:** 테이블 ↔ 차트 뷰 전환

**As a** 로드맵을 시각적으로 보고 싶은 개발자,
**I want to** 마크다운 테이블과 인터랙티브 차트 뷰를 토글로 전환하고,
**So that** 선호하는 방식으로 로드맵을 확인할 수 있다.

**Acceptance Criteria:**
- [ ] Given 로드맵 화면에서 "차트 보기" 토글을 켤 때, Then Mermaid.js 또는 커스텀 컴포넌트로 타임라인 간트 차트가 렌더링된다.
- [ ] Given 차트 뷰에서 현재 진행 단계는, Then 오늘 날짜 기준으로 하이라이트된다.
- [ ] Given 다시 "테이블 보기" 토글을 켜면, Then 마크다운 테이블로 즉시 전환된다.

## Epic 5: 인터랙티브 커리어 코칭 챗
> 사용자가 채팅으로 AI와 실시간 대화하면서 로드맵을 조정하고 세부 계획을 정교화할 수 있다.

### US-013 | 🔴 Must | AI 코칭 챗 대화

- **Page:** 챗 인터페이스
- **Feature:** 컨텍스트 인식 AI 대화

**As a** 로드맵에 대해 추가 질문이 있는 개발자,
**I want to** 챗으로 AI에게 질문하고 즉각적인 답변을 받고,
**So that** 모호한 부분을 빠르게 해소하고 학습 방향을 조정할 수 있다.

**Acceptance Criteria:**
- [ ] Given 챗 입력창에 메시지를 전송했을 때, Then 3초 이내에 AI 응답이 시작(스트리밍)된다.
- [ ] Given 이전 대화 맥락이 있을 때, Then AI는 해당 맥락을 참조해 일관된 답변을 제공한다.
- [ ] Given 페이지를 새로고침하거나 재접속하면, Then 이전 대화 히스토리가 DB에서 복원된다.
- [ ] Given 챗 응답은 항상, Then 현재 설정된 목표 회사·직군·기간 컨텍스트를 기반으로 생성된다.

**Notes:** Gemini Flash mode 사용. 응답은 SSE 스트리밍으로 처리.

### US-014 | 🔴 Must | 챗 기반 로드맵 동적 수정

### US-016 | 🔴 Must | JD 크롤링 및 임베딩 저장

- **Page:** 백엔드 파이프라인 (어드민)
- **Feature:** JD 수집·임베딩·Vector DB 저장

**As a** 시스템 운영자,

**So that** 사용자가 항상 최신 JD 기반으로 갭 분석을 받을 수 있다.

**Acceptance Criteria:**
- [ ] Given 크롤링 파이프라인이 실행될 때, Then 수집된 JD는 텍스트 추출 → 청킹 → 임베딩 → Vector DB 저장 순으로 처리된다.
- [ ] Given JD가 DB에 저장될 때, Then 회사명·직군·수집일·원문 URL 메타데이터가 함께 저장된다.

- [ ] Given 크롤링 실패 시, Then 실패 로그가 기록되고 재시도 메커니즘이 동작한다.

**Notes:** Supabase pgvector 또는 Pinecone. 임베딩 모델은 text-embedding-3-small 또는 동급.

## 에픽 8: 이력서 최적화

### 에픽
**US-025: 이력서 최적화** — 커리어 플랜의 모든 체크리스트 항목을 완료했을 때 ATS 최적화 이력서를 자동 생성합니다.

### 유저 스토리

#### US-025: 이력서 최적화하기 버튼
**사용자로서** 커리어 플랜의 모든 체크리스트를 완료했을 때,  
**이력서 최적화하기 버튼을 클릭하여** 맞춤형 이력서를 생성하고 싶습니다,  
**그래서** 지원 직무에 즉시 활용할 수 있는 JD 매칭 이력서를 갖고 싶습니다.

**인수 조건:**
- [ ] "이력서 최적화하기" 버튼이 저장된 플랜 상세 페이지(`/dashboard/[id]`)에 표시됨
- [ ] 이전에 생성된 이력서가 없고 `completedTodosCount < totalTodosCount`인 경우 버튼 **비활성화** (disabled)
- [ ] 비활성 버튼 hover 시 툴팁 표시: "모든 플랜을 완료했을때 최적화된 이력서를 생성할 수 있습니다"
- [ ] 모든 할일이 완료되면 버튼 **활성화** (퍼플 그라디언트)
- [ ] 클릭 시 `POST /api/resume-optimizer` 호출
- [ ] 요청 진행 중 "생성 중..." 로딩 상태 표시
- [ ] 한 번 생성 후 페이지를 새로고침해도 "✓ 생성 완료" 상태가 영구 유지됨 (마운트 시 `optimized_resumes` Supabase 조회로 상태 복원)
- [ ] "✓ 생성 완료" 버튼 클릭 시 캐시된 데이터로 결과 모달 재오픈 (API 재호출 없음)
- [ ] "✓ 생성 완료" 버튼은 현재 할일 완료 여부와 관계없이 항상 클릭 가능

#### US-026: 이력서 내용 구성
**사용자로서** 최적화 이력서를 생성할 때,  
**고정된 ATS 친화적 템플릿을 따르기를** 원합니다,  
**그래서** 자동 스크리닝을 통과하고 적합성을 명확히 전달할 수 있습니다.

**인수 조건:**
- [ ] 다음 6개 섹션을 순서대로 포함: 개인정보, 핵심 성과, 주요 기술, 학력, 수상/자격증, 지원 동기
- [ ] 핵심 성과는 동사로 시작하는 3~5개 불렛포인트
- [ ] 지원 동기는 JD 적합성을 설명하는 5~6문장 단락
- [ ] 테이블 형식 금지 — 불렛포인트만 사용
- [ ] 갭 분석에서 도출된 JD 키워드가 자연스럽게 포함됨
- [ ] 완료된 커리어 플랜 활동이 지원 동기에 반영됨

#### US-027: 이력서 언어 자동 감지
